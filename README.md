# diakon-telemost

Высоконагруженная распределенная платформа для обмена сообщениями и медиавещания в режиме реального времени.

## Описание проекта

Проект направлен на проектирование и разработку отказоустойчивого серверного коммуникационного комплекса, рассчитанного на развертывание в изолированных корпоративных контурах с повышенными требованиями к защите информации.

Ключевой задачей разработки является исключение системных рисков повреждения памяти и уязвимостей удаленного выполнения произвольного кода, свойственных традиционным монолитным серверам связи на языках C и C++. Решение задачи достигается переходом на безопасную управляемую среду Java 21. Высокая пропускная способность при пиковых нагрузках обеспечивается комбинированием неблокирующего ввода-вывода сетевого ядра Netty и пула легковесных виртуальных потоков Project Loom.

## Архитектурные модули платформы

### Сетевой шлюз и диспетчеризация трафика
Модуль сетевого интерфейса строится на основе асинхронного каркаса Netty. Задача модуля заключается в приеме входящих сетевых подключений по протоколам TCP и UDP, парсинге WebSocket кадров и первичной валидации пакетов с использованием буферов без лишнего копирования данных в памяти.

### Диспетчер бизнес-событий
Внутренняя логика обработки комнат, координации состояний участников и обработки очереди текстовых сообщений изолируется в легковесных виртуальных потоках. Такой подход исключает зависание системных потоков операционной системы при выполнении блокирующих обращений к внешним сервисам.

### Слой оперативного управления состоянием
Для хранения активных сессий, списков участников в конференциях и оперативных метаданных медиапотоков задействуется СУБД Tarantool. Размещение оперативных данных в оперативной памяти гарантирует минимальное время отклика на сигнальные события в пределах долей миллисекунды.

### Слой постоянного хранения данных
Для долговременного сохранения истории чатов, системных журналов и конфигураций профилей используется реляционная база данных PostgreSQL. Операции долговременной записи выносятся в асинхронный контур, чтобы исключить деградацию скорости сигнального ядра.

### Медиамаршрутизатор
Компонент маршрутизации медиатрафика базируется на стандартах WebRTC. Основной задачей слоя является прием, коммутация и ретрансляция входящих видеопотоков и аудиопотоков между подключенными пирами внутри активной комнаты без необходимости их перекодирования на стороне сервера.

## Протоколы взаимодействия

* Сигнальный протокол: WebSocket с передачей структурированных пакетов для синхронизации статусов микрофонов, видеокамер, входа и выхода участников.
* Текстовый чат: Передача сообщений внутри установленного WebSocket соединения с немедленной рассылкой по активным подписчикам комнаты.
* Медиавещание: WebRTC с использованием протоколов SRTP и UDP для обеспечения минимальной задержки трансляции медиаконтента.

## Целевые технические показатели системы

* Максимальная расчетная нагрузка на экземпляр: до 5000 одновременно активных сетевых соединений.
* Задержка доставки текстовых сообщений: перцентиль p99 не более 50 миллисекунд.
* Задержка передачи ключевых кадров медиапотока: перцентиль p95 не более 150 миллисекунд.
* Модель отказоустойчивости: сохранение работоспособности сигнального слоя при пиковой деградации сетевых каналов отдельных участников.

## Технологический стек

* Сетевой каркас и рантайм: Java 21, Netty Framework, Project Loom
* Оперативное состояние комнат: Tarantool
* Персистентное хранилище: PostgreSQL
* Протоколы взаимодействия: WebSocket, WebRTC
* Системы сбора метрик: Prometheus, Grafana
* Нагрузочное тестирование: k6

## План реализации и контрольные точки

### 1. Архитектурное проектирование
Формализация формата сериализации управляющих пакетов. Проектирование схемы таблиц реляционной базы данных и структуры спейсов в Tarantool.

### 2. Разработка сетевого каркаса на Netty
Реализация входного пайплайна обработки WebSocket соединений. Настройка декодеров сообщений и механизма передачи управляющих сигналов в пул виртуальных потоков.

### 3. Реализация логики координатора комнат
Создание модулей создания комнат, аутентификации пользователей и рассылки текстовых сообщений. Подключение драйвера Tarantool для синхронизации состояний в реальном времени.

### 4. Разработка подсистемы медиавещания
Интеграция сетевых механизмов согласования WebRTC соединений. Реализация пересылки пакетов между клиентами.

### 5. Нагрузочное профилирование и телеметрия
Написание сценариев стресс-тестирования в утилите k6 для эмуляции поведения 5000 участников. Подключение метрик экспортера Prometheus, анализ использования оперативной памяти, мониторинг пауз сборщика мусора и фиксация задержек.
